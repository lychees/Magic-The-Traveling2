# 视觉与交互设计

> 本文是本次现代化界面的实施与验收规范。设计令牌入口为 `style.css`，简版见根目录 `DESIGN.md`；交互依赖的规则见[玩法设计](玩法设计.md)，DOM/API 见[开发指南](开发指南.md)。所有主题共享信息架构和规则，不用视觉差异隐藏功能。

## 1. 设计原则

1. **任务先于装饰**：组牌时先看卡库、筛选和牌组完成度；战斗时先看英雄、三排、当前阶段和主操作。烫金、皮革和像素材质退居其次。
2. **一屏一个主操作**：构筑是“开始战斗/提交牌组”，部署是“开始战斗/完成部署”，奖励是“选择一件/继续”。次要操作不能同样高亮。
3. **状态不只靠颜色**：选中要有描边/勾选/文字，守备要有姿态和“守备”，不可用要有原因，增益要能追溯来源。
4. **渐进披露**：首轮只教预设、出牌、守备、战术和开战；完整词条、评分与高级手势留在详情/规则中。
5. **鼠标、触屏、键盘等价**：拖拽和双击是效率捷径，不是唯一入口；按钮、Enter/Space 与详情操作必须覆盖核心任务。
6. **表现服从结算**：1x/2x/4x、动画、音效和 3D 不能改变规则；减少动态效果后仍能理解发生了什么。
7. **三主题同构**：换主题不换 DOM 语义、操作顺序、信息含义和命中区域。

## 2. 信息架构

### 2.1 一级任务

- **构筑与对战**：人机、同机双人、联机/观战；卡库、牌组、规则配置和预设。
- **闯关模式**：选阵营、分支地图、牌组/遗物、节点奖励与结算。
- **收藏**：开卡包、阵营卡包/卡盒、3D 集卡册、纪念堂。
- **工具**：3D 检视、卡牌编辑器、主题、音效、规则说明。
- **开发者模式**：低频调试入口，不与主任务争夺视觉权重。

界面分为两种体验模式：

- **Operate（任务型）**：构筑、战场、编辑器、远征地图。密度、扫读、键盘和错误恢复优先。
- **Experience（展示型）**：3D 检视、撕包、卡盒、集卡册。材质与动效优先，但关闭、静音、减少动态仍可用。

### 2.2 导航原则

- 当前模式有文字和选中态；人机/热座/联机切换不暗中清空两套牌组选择。
- 商店/收藏/编辑器不是对局模式，不与“人机对战”做成含义相同的切换。
- 返回构筑保留本机选择；离开联机会关闭连接并有明确状态。
- 破坏性操作（放弃远征、删除自定义卡等）说明后果；普通加牌/筛选不需要确认打断。

## 3. 构筑页结构与线框

### 3.1 桌面（≥1280px）：三栏

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 使魔卡牌对战 · 组牌   金币   闯关  集卡册  卡包  编辑器  主题            │
├───────────────┬──────────────────────────────────────┬───────────────────┤
│ ① 对局设置     │ ② 卡库                               │ ③ 当前牌组         │
│ 人机/热座/联机 │ 搜索 [卡牌名称 / 描述关键字____]      │ 我的牌组  28 / 60  │
│ 模式说明/联机  │ 排序 [费用/评分/名称]                 │ 可开战 / 还差 N 张 │
│ 预设卡组       │ 阵营 费用 类型 派系 词条 [重置]       │ 牌组列表（滚动）    │
│ 随机牌组       │                                      │ 法力曲线 0…7+      │
│ 对局规则       │ 按阵营/法术分区的卡牌网格             │ 阵营与法术统计      │
│               │ [费][名][评分][已选 n/max]            │ 清空 / 3D 检视     │
│               │                                      │ [开始战斗]          │
└───────────────┴──────────────────────────────────────┴───────────────────┘
```

- 左栏回答“用什么模式与规则玩”；中栏回答“能选什么”；右栏回答“现在能否开战”。
- 左/右栏可粘性定位，卡库主区域独立滚动遵循浏览器自然滚动；三栏都不能把主按钮挤出不可达位置。
- 卡牌网格按可用宽度填充，不为保持固定列数把文字压到不可读。

### 3.2 中屏（801–1279px）

```text
┌────────────────────────────────────────┐
│ 顶栏 / 模式与设置区（横贯，可换行）     │
├────────────────────────┬───────────────┤
│ 卡库：搜索/筛选/网格    │ 牌组与主操作   │
└────────────────────────┴───────────────┘
```

设置区横贯并折叠次要说明；卡库与牌组保持并列，避免在每次加牌后长距离往返。

### 3.3 窄屏（≤800px，重点验收 390px）

```text
┌──────────────────────┐
│ 标题 / 金币 / 菜单    │
│ 模式与预设（换行）    │
│ 搜索 / 筛选 / 排序    │
│ 卡牌网格              │
│ 牌组完成度与列表      │
│ 曲线 / 阵营统计       │
│ 开始战斗（主操作）    │
└──────────────────────┘
```

- 单栏保持“设置 → 卡库 → 牌组”的顺序；牌组完成度、列表、分析与主操作位于牌组区域，不依赖 hover。
- 主操作保持易触达，不依赖 hover；顶栏允许换行或分组，不把十几个按钮压缩成横向滚动条。
- 卡牌按容器自适应，费用、名称、攻/甲/血、已选数量不能被裁掉。
- 390×844 下不得出现页面级意外横向滚动；牌组/卡库内部的纵向滚动可以保留。

## 4. 战场结构与线框

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 使魔卡牌对战     第 3 轮 · 部署阶段       音效  返回构筑                  │
├──────────────────────┬───────────────────────────────────────────────────┤
│ 战斗记录 / 轮次摘要   │ 敌方英雄 生命 14/20 法力 3/3  手牌数 牌库 墓地   │
│                      │ 敌方后排 → 中排 → 前排（朝中线）                   │
│ 第 2 轮战报           │ 空中（仅有飞行时显示）                            │
│ 你伤 4 · 对手伤 6     │ ------------------------------------------------- │
│ 阵亡 1 / 2            │ 战术：[猛攻] [坚守] [集结]  本轮：猛攻             │
│                      │ 速度：[1x] [2x] [4x]      [开始战斗]             │
│ [展开详细记录]        │ ------------------------------------------------- │
│                      │ 我方前排 → 中排 → 后排                            │
│                      │ 我方英雄 生命 16/20 法力 3/3  牌库 墓地           │
│                      │ 手牌：点击打出 / 拖到指定排 / 详情                  │
└──────────────────────┴───────────────────────────────────────────────────┘
```

信息优先级：

1. 当前轮次/阶段、双方英雄生命和“开始战斗/完成部署”。
2. 三排/空中、当前战术、可用手牌和法力。
3. 本轮摘要、单位状态、牌库/墓地计数。
4. 完整战斗日志、规则说明和长期说明。

桌面记录区可侧置/粘性；≤1100px 时记录移到战场下方，≤800px 时指挥台单列，≤520px 时手牌与排内允许横向滚动。窄屏把摘要放在主操作附近，详细日志折叠到下方。进攻阶段锁住部署操作并显示“战斗中…”，热座/联机等待时明确写“等待某方部署…”，不能只让一个禁用按钮悬空。

## 5. 设计令牌

### 5.1 色彩

默认主题以 `:root` 为基线；新组件优先消费令牌，不再新增相近的随意深色。

| Token | 默认值 | 用途 |
| --- | --- | --- |
| `--bg` | `#0e100f` | 页面底色 |
| `--panel` | `#191c19` | 一级面板、浮层、卡片内容面 |
| `--panel-2` | `#111411` | 二级面、侧栏、内嵌区域 |
| `--panel-3` | `#22231d` | 三级强调面 |
| `--line` | `#30342e` | 弱分隔、默认描边 |
| `--line-2` | `#4b493b` | 强分隔、输入框/重点边界 |
| `--text` | `#f0eadc` | 主正文 |
| `--text-2` | `#d8d2c4` | 次级正文、表单值 |
| `--muted` | `#a29d8f` | 辅助说明 |
| `--muted-2` | `#756f62` | 非关键装饰/极弱提示，不承载必要信息 |
| `--gold` | `#d4b571` | 标题、品牌、重点边框 |
| `--gold-bright` | `#f2d58d` | 选中、奖励、高亮数值 |
| `--gold-dim` | `#8b7042` | 默认金色按钮边界 |
| `--accent` | `#83b8c9` | 链接、信息、焦点环 |
| `--success` | `#91bd8a` | 成功、恢复、合法 |
| `--danger` | `#df8a7e` | 危险、失败、破坏操作 |
| `--ink` | `#11130f` | 浅金按钮上的深字 |

语义补充：成功/恢复使用绿，危险/失败使用红，法力/信息使用蓝，士气负态使用灰暗/低落标识，法术派系沿用土绿/水蓝/火红/气青。语义色必须同时配文字、符号或形状；浅色城堡/元素卡面使用深字变体。

对比要求：正文和关键数值目标至少 4.5:1，大号文字至少 3:1；禁用态可以降低对比，但必须有禁用原因的可读说明。`--muted-2` 不用于关键错误、当前阶段或按钮用途。

### 5.2 Typography

| 角色 | 基线字号/字重 | 用途 |
| --- | --- | --- |
| display | 20px / 700 | 页面标题、结果标题；可有 1–2px 字距 |
| h2 | 15px / 700 | 区块、牌组、摘要标题 |
| body | 14px / 400 | 正文、按钮、列表 |
| label | 13px / 400 | 表单标签、字段名 |
| meta | 12px / 400 | 辅助说明、状态描述 |
| data | 12–14px / 600–700 | 攻甲血、生命、法力、金币、计数 |

- 字体栈以 `PingFang SC`、`Microsoft YaHei` 和系统 sans-serif 为主；不依赖远程字体才能显示中文。
- 正文行高约 1.45–1.6，数值行高 1.2；中文正文不额外拉字距。
- 像素主题可用 `Courier New`、`SimSun`、monospace 形成风格，但中文长描述仍须可读。
- 不把全部说明压到 10px；卡面可缩略，详情必须提供完整可读文本。

### 5.3 间距、圆角、层级

| Token/规则 | 值 | 用法 |
| --- | --- | --- |
| `--s1`～`--s6` | 4 / 8 / 12 / 16 / 24 / 32px | 4px 基线 |
| 组内间距 | 8px | 按钮组、徽标、字段 |
| 组间间距 | 16–24px | 信息区块 |
| 页面边距 | 12–16px | 桌面；窄屏不小于安全边距 |
| `--r-md` | 9px | 卡牌/较大控件 |
| `--r-lg` | 14px | 面板/浮层 |
| `--r-sm` | 6px | 输入、标签、普通按钮 |

默认主题以 1px 描边表达普通层级，模态使用 `--shadow-modal: 0 20px 70px rgba(0,0,0,.62)`。拟物的内阴影和像素的硬阴影是主题材质，不额外代表可点击或更高优先级。

Z 层级按“页面 < 粘性侧栏 < 战斗特效 < 普通浮层 < 交机隐私/编辑器 < 3D 检视”管理；新浮层不能覆盖交机隐私屏而泄露手牌。

## 6. 组件规范

### 6.1 按钮与选择控件

| 类型 | 使用场景 | 状态要求 |
| --- | --- | --- |
| 主按钮 `.btn-primary` | 开始战斗、完成部署、确认奖励 | 默认/hover/active/focus/disabled；禁用原因邻近可读 |
| 普通按钮 `.btn` | 预设、筛选操作、打开工具 | 不与主按钮争夺高亮 |
| 危险按钮 `.btn-danger` | 清空、删除、放弃远征 | 文字说明对象和后果 |
| 弱按钮 `.btn-ghost` | 返回、次要关闭 | 仍保留可见边界和焦点 |
| 分段选择 | 战术、战斗速度 | 当前项有选中态和 `aria-pressed` 或等价单选语义 |
| 原生选择框 | 主题、排序、阵营商店 | 有可访问名称，不只靠 `title` |

关键触控目标以 44×44px 为验收目标；视觉图标可以较小，但命中区不能过小。disabled 不响应点击，hover 不能模拟可点击。

### 6.2 卡牌

统一信息顺序：

`费用 → 名称/传说标记 → 阵营或法术派系 → 立绘 → 词条/效果 → 攻/甲/血（单位） → 拥有/已选/评分（构筑）`

- 评分是辅助信息，不与费用同形同色；已选 `n/max` 与拥有数分开。
- 法术使用派系徽标和“法术”文字，不能只靠紫边；单位三围顺序固定为攻/甲/血。
- 卡面省略的描述可在详情查看；词条徽标不能只靠 hover title 才能理解。
- 浅色阵营卡使用深字，其他卡使用浅字；增益数值在基础值之外有来源说明。

### 6.3 战场单位与状态

| 状态 | 视觉 | 文本/语义 |
| --- | --- | --- |
| 可收回 | 青色虚线/明确提示 | “本轮可收回”，单击执行，双击详情不收回 |
| 守备 | 横向占 2 宽 + 守备徽标 | “守备：不主动攻击，同时反击” |
| 有效飞行 | 空中区域/浮起 + 飞行标识 | 不参与地面宽度；远程伤害加倍 |
| 盖牌 | 卡背 + “翻面表示/守备” | 对手看不到名称与数值 |
| 士气 | 正负数值 + 高/低落非颜色线索 | 显示当前值与概率解释 |
| 中毒/失明/石化/觉醒 | 独立徽标和数值 | 显示层数/剩余轮数/觉醒进度 |
| 战术 | 战场级本轮标识，不只画一张小图标 | “本轮·猛攻：攻 +1”等 |
| 合法目标 | 高亮边框 + 目标模式说明 | 点击空白/取消退出，不非法扣费 |
| 不可操作 | 降低强调 + 原因 | 战斗中、非部署方、法力不足等分别说明 |

数值变化保留基础值与当前值：详情显示“攻 4（基础 3）”“甲 3（基础 2）”等，并对当轮战术、永久增益、光环、遗物使用一致措辞。

### 6.4 浮层、详情和奖励三选一

- 浮层有可见标题、关闭按钮和中文可访问名称；允许取消的浮层支持 Esc 和遮罩关闭。
- 打开后焦点进入浮层，Tab 不落到背后可操作内容；关闭后回到触发控件。
- 墓地/祭品/多选复活显示费用预算与已选值；无合法目标时说明原因。
- 卡牌/遗物三选一每项都是完整按钮：名称、效果、选择状态清晰；选择后整组锁定，防止连点重复领取。
- 观战模式隐藏操作，不给看似可用却总会失败的按钮。

### 6.5 轮次摘要

战场使用紧凑摘要，先回答“本轮双方英雄受伤与单位阵亡多少”，不把完整日志压缩成难以扫读的长卡片：

```text
第 3 轮战报 · 你伤 4 · 对手伤 6 · 阵亡 1 / 2 · 对手获胜
```

- 摘要位于轮次/阶段区域；交战未完成时标“交战”，完成后标“战报”。伤害与阵亡为 0 也如实显示。
- `outcome` 未结束为 `ongoing`，结束时映射胜/负/平；`player/enemy` 必须经当前身份和视角转为正确中文，不能固定把 player 写成“你”。
- 战术名称、具体阵亡单位、士气额外行动和遗物触发等在详细战斗日志按时间顺序查看；`title` 中的关键结果只是辅助，不是键盘用户唯一入口。
- 结构化 `state.roundSummary` 另保留起止生命、阵亡名单、双方战术和 `keyResults`，供 UI/探针使用；不要为了让所有字段挤进一行而牺牲可读性。
- 详细记录不被摘要覆盖；窄屏将摘要留在主操作附近，完整日志置于后续可滚动区域。

## 7. 三主题

主题由 `#theme-select` 选择，写入 `<html data-theme="…">` 并保存到 `mtcg-theme`。

| 值 | UI 名 | 视觉语言 | 必须保持不变 |
| --- | --- | --- | --- |
| `default` | 深色烫金（旧称“原版”） | 近黑蓝紫、细金边、清晰面板、克制高光 | 全部功能与状态 |
| `skeuo` | 皮革拟物（旧称“拟物”） | 皮革/羊皮纸、压印金属、内阴影和材质渐变 | 字号层级、焦点、命中区、文案 |
| `pixel` | 像素 RPG | 粗描边、零圆角、硬阴影、像素化图像与等宽字体感 | 三排关系、数值、响应式顺序 |

实施约束：

1. 新 chrome 组件必须在三个主题各验收一次，不允许只写 `:root` 默认色后被主题背景吞掉。
2. 卡牌阵营色是内容语义，主题不能任意改成无法区分的同色。
3. 像素主题的硬阴影不能遮挡焦点环；拟物纹理不能降低正文对比。
4. 主题不切换规则、AI、随机序列、卡牌价格或速度。
5. 3D 全息材质是展示层扩展，可与 chrome 主题不同，但关闭/键盘/减少动态偏好仍有效。

## 8. 动效与音效

### 8.1 动效节奏

| 反馈 | 基线 | 要求 |
| --- | --- | --- |
| hover/按钮过渡 | 约 120ms | 不造成布局跳动 |
| 单击/双击区分 | 220ms | 双击详情取消未执行的单击动作 |
| 攻击突进/受击/死亡 | 约 450ms | 同时有数值/日志，不依赖动画判断 |
| 士气特效 | 约 600ms | 正负方向与文字一致 |
| 法术闪光 | 约 650–750ms | 不无限遮挡操作 |
| 高费单位降临 | 约 950ms | 不延迟或改变实际结算 |
| combatTick | 650ms ÷ 速度倍率 | 只改表现等待，不改随机/规则 |

### 8.2 减少动态效果

尊重 `prefers-reduced-motion: reduce`：

- 移除/缩短非必要突进、晃动、浮起、脉冲、翻牌旋转、3D 装饰动画；保留即时状态切换。
- 不用自动平滑滚动或大视差；奖励三选一和轮次摘要直接出现。
- 战斗速度仍按用户选择工作，但结果与日志不能被跳过。
- 3D 检视提供静态可理解卡面和退出方式；WebGL 不可用时回退 2D 详情。

### 8.3 音效

- WebAudio 程序合成，无外部音频文件：召唤、命中、反击、死亡、治疗、阶段、胜负、卡包、翻牌、法术、士气、撕包/卡盒、翻页和领奖。
- 首次用户手势后才创建/恢复 AudioContext；未交互前不得强行播放。
- `sfx-toggle` 切换静音，状态保存到 `sfx-muted`；按钮有“开启音效/关闭音效”的可访问名称。
- 同一 tick 同名音效节流，4x 不能形成刺耳叠音；静音不影响计时与结算。

## 9. 响应式与触屏

| 检查项 | 桌面 | 中屏 | 390px 窄屏 |
| --- | --- | --- | --- |
| 构筑 | 三栏 | 设置横贯 + 两栏 | 单栏、筛选/统计渐进披露 |
| 战场 | 主战场 + 记录区 | 主战场优先，记录可折叠 | 摘要近主操作，详细日志下方 |
| 卡牌 | 自适应网格 | 减少列数 | 名称/三围/费用不裁切 |
| 主操作 | 清晰固定层级 | 不随侧栏挤出 | 易触达、文案不省略关键动作 |
| 浮层 | 限宽、限高 | 内部滚动 | 宽度减安全边距，按钮可点 |
| 导航 | 完整展示 | 合理换行 | 分组/换行，无页面横溢 |

- 拖拽之外保留点击出牌与守备按钮；同排精确排序可视为桌面增强，但触屏必须有可用的默认落位。
- 不用禁止页面缩放来解决布局；保留浏览器 pinch zoom。
- 触屏长按战术预览不能成为查看基础详情的唯一方式。
- 横竖屏切换后重算布局，不保存像素坐标作为游戏状态。

## 10. 键盘与可访问性

### 10.1 键盘契约

| 按键 | 行为 |
| --- | --- |
| Tab / Shift+Tab | 按 DOM 顺序移动可见焦点，不跳入隐藏界面 |
| Enter / Space | 激活聚焦按钮；在可操作卡牌上执行其默认动作（加入牌组/出牌等） |
| Shift+Enter | 查看聚焦卡牌详情，等价于双击的信息入口 |
| Esc | 关闭允许取消的详情、查看器、3D 或目标选择；不用于确认破坏操作 |
| 原生方向键 | 在 select 等原生控件中按浏览器行为工作 |

不额外发明未实现的全局快捷键。输入框内按键不得误触出牌或清空。

### 10.2 语义与焦点

- 交互元素优先使用 `button/input/select/summary`；用 `div` 呈现的卡牌必须有等价键盘和角色/名称，而不是只加 `onclick`。
- 图标按钮提供中文名称；卡牌名称包含费用、攻甲血和关键状态。装饰立绘/符号不重复朗读。
- 当前战术/速度有程序化选中态；当前模式、禁用和展开状态同样可感知。
- 阶段和轮次摘要可用 `aria-live="polite"` 适度通知；逐 tick 日志不连续抢读，错误用明确文本。
- 浮层管理焦点与背景隔离；交机隐私屏不能通过 Tab 看到背后的手牌。
- focus-visible 使用至少 2px `--accent` 焦点环，不能被 `overflow:hidden` 或主题阴影吞掉。
- 不以“通过某认证”作未经测试的声明；每次新组件按键盘、缩放到 200%、减少动态和高对比场景实测。

## 11. 新手引导与规则说明

### 11.1 首轮引导

`mtcg-guide-v1` 用 JSON 的 `builderDone` / `battleDone` 布尔字段记录组牌/战斗引导完成情况；完成后不强制重复，存储不可用时不能阻断游戏。

引导只覆盖当前可执行动作：

1. **组牌**：指向预设与牌组完成度，“选一套预设即可立即开战，也可以逐张构筑”。
2. **首轮部署**：指向手牌和法力，“点击费用够用的卡牌打出”。
3. **姿态**：有合适单位时提示“守备不主动攻击，但能持续反击”。
4. **战术**：解释三项均只持续本轮，允许跳过和改选。
5. **开战/速度**：指向主按钮；2x/4x 标为“只加快表现”。

规则说明保持随时可查；卡牌详情、词条解释和摘要是第二层教学，不在开场一次性展示全部 398 卡或完整结算公式。

### 11.2 文案术语

- 统一用“轮”描述 deploy+combat，“部署阶段/进攻阶段”描述 phase；战术文案写“本轮”，不混用“永久”“下回合”。
- 统一用“攻击/有效护甲/当前生命”“士气”“守备表示”“翻面表示”“轮次摘要”。
- `assault/guard/rally` 是开发 ID，玩家只看“猛攻/坚守/集结”。
- 按钮写动作：“开始战斗”“完成部署”“选择这件遗物”“恢复 8 生命”，避免“确定”“好的”承担不明后果。
- 错误写原因 + 下一步，不写“非法操作”“未知错误”或责怪玩家。

## 12. 中文 UX 文案与状态

以下是实现与回归的文案基线；动态数值用真实状态替换，不能写死。

| 场景 | 推荐文案 | 辅助/行为 |
| --- | --- | --- |
| 空牌组 | “还没有选择卡牌。点击卡库中的卡牌，或使用一套预设。” | 显示“还差 20 张”，主按钮禁用 |
| 牌组未达下限 | “还差 {20-n} 张即可开战。” | 不只显示红色 |
| 牌组合法 | “{n} / 60，可以开战。” | 主按钮启用 |
| 筛选无结果 | “没有符合当前条件的卡牌。请更换关键词或重置筛选。” | 提供“重置筛选” |
| 同名已满 | “【{卡名}】已达到本牌组携带上限。” | 已选 `n/max` 可见 |
| 法力不足 | “法力不足：打出【{卡名}】需要 {cost} 点，当前只有 {mana} 点。” | 不扣费、不移除手牌 |
| 无合法法术目标 | “【{卡名}】当前没有合法目标。” | 保持手牌，可取消目标模式 |
| 空排/空墓地 | “这一排还没有单位。” / “墓地为空。” | 不用错误色 |
| 对手部署 | “等待 {玩家名} 完成部署…” | 禁用本地部署动作 |
| 战斗中 | “进攻阶段：单位正在自动行动。” | 主按钮显示“战斗中…” |
| 未选战术 | “本轮未选择战术，不会获得战术增益。” | 允许直接开战，不强制 |
| 速度切换 | “战斗速度 {n}x：只改变表现，不改变结果。” | 当前项有选中态 |
| 遗物已拥有 | “当前远征还没有遗物。精英或 Boss 战后可三选一。” | 有后续获取指引 |
| 奖励候选 | “选择一件遗物，效果将在本次远征中持续。” | 选择后整组锁定 |
| 旧档恢复 | “已恢复上次远征进度。” | 缺遗物字段按空列表，不清档 |
| 本地存储不可用 | “浏览器无法保存进度；本次可继续游玩，但关闭页面后可能丢失。” | 不阻断开局 |
| PeerJS 加载 | “正在加载联机组件…” | 本地模式仍可用 |
| PeerJS 不可用 | “联机组件加载失败。你仍可进行人机或同机双人对战。” | 提供重试/返回本地 |
| 正在连接 | “正在连接房间 {code}…” | 不提前显示“已加入” |
| 连接失败 | “未能连接房间。请检查房间码、密码和网络后重试。” | 保留输入，不暴露密码 |
| 房间已满/已开始 | “房间已满” / “对局已开始，无法加入为玩家。” | 可按支持情况选择观战 |
| 动作被拒 | “动作未执行：{房主返回原因}。” | 等下一权威快照，不本地伪造成功 |
| 断线 | “对方已断线，对局结束。” / “房间已关闭。” | 不继续推进战斗 |
| 卡面/3D 加载 | “正在准备 3D 卡面…” | 避免长时间无反馈 |
| WebGL 不可用 | “当前环境无法显示 3D，已改为 2D 卡牌详情。” | 保留全部规则文字 |
| 图片失败 | 显示卡名、派系与数值的占位卡面 | 不出现空白可点击区 |
| 清档/清缓存提示 | “收藏、金币和远征保存在此浏览器；清除站点数据会丢失。” | 不暗示已有云同步 |

加载状态只用于真实异步过程（PeerJS、3D、卡面生成、连接）；同步 localStorage 读取不制造假进度条。错误发生时优先保留用户输入和当前合法状态。

## 13. 界面验收清单

每个主题至少走一遍：

1. 空牌组 → 预设 → 搜索/筛选/排序 → 加/减卡 → 合法开战。
2. 首轮出牌 → 调排/守备 → 战术改选 → 1x/2x/4x → 战斗摘要 → 下一轮战术清除。
3. 双击/Shift+Enter 详情 → 关闭；牌库/墓地查看；法术选目标与取消。
4. 精英/Boss 奖励 → 查看/选择遗物 → 刷新恢复。
5. 卡包/卡盒、集卡册、编辑器、3D 检视打开与关闭。
6. 1440×900、1024×768、390×844；鼠标、仅键盘、减少动态效果三种条件。
7. 人机、热座隐私屏、联机 guest/观战各自只显示该身份可见的信息与操作。
