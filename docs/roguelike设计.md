# Roguelike 闯关模式设计

> 本文描述当前远征实现及扩展约束。玩法示例与平衡指标见[玩法设计](玩法设计.md)，字段/迁移见[开发指南](开发指南.md)。历史“后续方向”全部移到文末并明确标为未实现。

## 1. 设计目标

- 用分支路线和规则型 Boss 提供“解题”体验，复用 13 阵营、398 卡、三排/士气/守备/盖牌与收藏经济。
- 让玩家同时管理**单场胜负、跨节点生命、牌组结构和遗物协同**，而不是只堆最高评分卡。
- 给构筑修正留出口：抓牌可跳过、商店可删牌、篝火有稳定治疗、遗物三选一不重复。
- 所有循环必须有每轮/每阶段/每单位/每场计数；纪念卡只做收藏，不制造永久强度失控。

## 2. 开始与起始牌组

1. 从 13 阵营中选择一个。
2. 找到该阵营的“阵营 · 标准”预设，将卡牌按费用升序、同费评分降序排列，取前 15 张作为起始牌组。
3. 创建 25/25 英雄生命、10 列地图及连线、空路径、空遗物列表，保存到 `mtcg-run` 并进入地图。

普通对局默认 20 生命；远征继承生命是独立规则，不能混用。

## 3. 地图与选路

### 3.1 10 列结构

- 第 1 列：普通战斗起点。
- 第 6 列：中 Boss，固定单节点。
- 第 10 列：最终 Boss，固定单节点。
- 其余列：从对应节点池随机保留 2–3 个节点，包括战斗、精英、篝火、商店、事件；前后期权重不同。

### 3.2 连线约束

- 地图和边在开局一次生成并保存，不在每次渲染重 roll。
- 单节点列向下一列全连出/全汇入；多节点列通常连接下一列最近的 1–2 个节点，并保证下一列每个节点至少一条入边。
- 只能选择与上一列实际所选节点连通的当前列节点；未连通置灰，选择后路径锁定。
- `RUN.floor` 是当前列下标，`RUN.path` 记录已走节点下标，`RUN.curNode` 记录当前节点；界面显示“第 floor+1 / 10 层”。

## 4. 节点规则

| 节点 | 规则 |
| --- | --- |
| 战斗 | 普通敌方牌组；胜利 30 金币，随后卡牌三选一，可跳过 |
| 精英 | 更强牌组；胜利 60 金币，先独立遗物三选一，再进入原有卡牌奖励 |
| 篝火 | 二选一：恢复 8 生命；或选牌进行 70% +1攻/+2血、30% 销毁的风险强化 |
| 商店 | 永久金币消费，可重复：删牌 50、随机本阵营卡 100、恢复 6 生命 40；离开后前进 |
| 事件 | 40% 获得 80 金币；30% 获得随机本阵营卡；30% 恢复 10 生命 |
| 中 Boss | 第 6 列，敌方英雄 25；胜利 120 金币，遗物三选一后进入卡牌奖励 |
| 最终 Boss | 第 10 列，敌方英雄 30；胜利 300 金币，先处理可用的遗物奖励，再进入通关奖励 |

所有治疗不超过 `RUN.maxHp=25`。风险篝火强化克隆当前卡牌对象，只改变该张远征牌，不修改 `CARD_DEFS` 或普通收藏。

### 4.1 抓牌池

- 候选由本阵营卡池权重 ×2 加中立卡池组成，不含纪念卡。
- 随机取至多 3 种不同卡，可跳过；不是按评分从高到低直接发放。
- 商店“随机本阵营卡”只从本阵营非纪念卡抽取。

### 4.2 敌方与 Boss 规则

| 修饰 | 效果 | 设计目的 |
| --- | --- | --- |
| 万籁俱寂（中 Boss 随机） | 敌方每轮开始召唤一个骷髅到前排 | 逼迫抢节奏，检查清场与持续交换 |
| 心如止水（中 Boss 随机） | 全场单位士气锁定为 0 | 暂时移除士气解法；集结/昂扬战旗不能突破 |
| 巨龙威压（最终 Boss） | 敌方所有单位攻击 +1 | 检验构筑成型与基础交换 |

普通节点偏中低费牌组，精英提高费用上限与同名携带，Boss 按修饰选择阵营/高费池；具体生成入口为 `enemyDeckFor`。

## 5. 生命、胜负与纪念

- 每场胜利后 `RUN.hp=max(1,state.player.hp)`，下一节点继续；篝火/商店/事件是主要恢复来源。
- 双方同死算“涉险过关”，以 1 血继续；单方失败进入纪念流程，不发普通胜负奖励。
- 通关在已有 300 金币之外，将随机一张费用 ≥7 的本阵营卡加入永久收藏。
- 失败纪念卡：
  - `name='纪念·'+阵营+'远征'`
  - `atk=min(12,总击杀)`，`hp=min(15,max(1,存活轮数))`，`arm=0`
  - `cost=min(10,ceil(总击杀/2))`，`rating=60`
- 纪念堂最多保存 30 张；纪念卡用于收藏，不作为高强度构筑奖励。

## 6. 本次 8 种遗物

遗物只作用于 `RUN.active && RUN.inBattle` 的远征玩家侧，普通对局和敌方无效。定义表是 `RUN_RELICS`，存档只存 ID。

| ID | 中文 | 精确效果 |
| --- | --- | --- |
| `warDrum` | 战鼓 | `recalcAuras` 时己方全队攻击 +1 |
| `stoneAegis` | 磐石徽记 | `effArmor` 时己方全队有效护甲 +1 |
| `longBow` | 猎手长弓 | `recalcAuras` 时己方远程单位攻击 +2 |
| `spikedShield` | 荆棘盾牌 | `executeCounter` 时己方反击伤害 +2，普通/守备反击按各自规则 |
| `rallyBanner` | 昂扬战旗 | 每轮进攻阶段开始己方全军士气 +1，记录实际提升；受免疫/上限/心如止水限制 |
| `bloodChalice` | 鲜血圣杯 | 己方单位用攻击或反击击杀敌方单位时，英雄恢复 2 点生命 |
| `arcaneTome` | 奥术典籍 | 每场节点战初始 5 张后额外摸 2 张，再进入正常轮开始；遵守手牌上限 |
| `phoenixFeather` | 凤凰之羽 | 每场节点战第一个将在 `cleanupDead` 移除的己方单位以 1 血留场；每场重置，不保护英雄 |

### 6.1 协同与边界

- 战鼓/长弓与猛攻都是 `recalcAuras` 的攻击派生，卡牌 `baseAtk` 不被永久污染。
- 磐石徽记与坚守都进入有效护甲，会影响减伤和行动速度；法术与护甲穿透仍按原规则。
- 昂扬战旗在当轮集结之后触发；士气始终受 -10～+10、墓园/元素免疫和 Boss 锁 0 约束。
- 鲜血圣杯只由攻击/反击击杀触发，不把任意法术/毒杀都算作攻击击杀。
- 凤凰之羽挽救的单位不能同时进入 `roundSummary.unitsLost`；`state._relicState.phoenixFeatherUsed` 在每场 `initGame` 重置，不写入 RUN。

## 7. 奖励与存档时序

```text
战斗胜利
  → 记录生命/击杀/轮数并发节点金币
  → elite/boss/finalBoss 且仍有未拥有遗物
      → 从未拥有 ID 洗牌取至多 3 个
      → RUN._relicDraft + RUN._afterRelic 保存
      → 玩家选择一件：校验当前 panel、候选与未拥有，再 push ID
      → 清候选并保存
  → _afterRelic='draft'：进入原卡牌三选一
    _afterRelic='victory'：进入通关结算
```

- 候选排除已拥有遗物，同一 ID 不会重复获得；连点不能重复领取。
- 普通战斗不给遗物；8 件全拥有后不再制造空遗物页。
- 最终 Boss 的遗物选择在通关奖励前执行；这不是普通永久收藏卡包。
- 地图和奖励页显示当前遗物名称/描述；待三选一的候选也保存，刷新不能重 roll。

## 8. 存档字段与旧档迁移

核心键：`mtcg-run`。永久金币/收藏仍分别走 `mtcg-gold/mtcg-collection`，不是 RUN 的副本。

```js
RUN = {
  active, race, deck, floor, map, edges, path, curNode,
  hp, maxHp, kills, rounds, modifier,
  relics: [],                 // 已拥有 ID
  _relicDraft: null,          // 待选 ID[] | null
  _afterRelic: null,          // 'draft' | 'victory'
  _panel: 'map',
  inBattle: false,
}
```

迁移规则：

1. 缺 `relics` 的旧档补 `[]`，过滤无效 ID 并去重。
2. `_relicDraft` 只保留有效、未拥有的至多 3 个 ID；无效候选与 `_afterRelic` 一起清空。
3. 地图/边缺失或 `active` 不合法时按无有效远征处理，不影响永久收藏。
4. 每次关键选择后 `saveRun`；刷新恢复同一地图、路径、生命、牌组、遗物和待选奖励，不重新随机。
5. 放弃/失败继续/通关继续只清当前 RUN，不使用 `localStorage.clear()`，不删金币/收藏/纪念。

## 9. 新遗物评审清单

- 是否有真实引擎触发点和至少一个正例/一个边界例？
- 是否只影响远征玩家，且不会出现在普通 PvP？
- 是持续派生、每轮、每场还是一次性？计数放对 `state` 还是 `RUN`？
- 与三种战术、士气免疫、反击、复活、手牌/场上的上限是否冲突？
- 候选/已拥有是否只存 ID，刷新是否稳定，旧档是否能恢复？
- 是否至少有一个协同和一个无效/受限场景，而非无条件必选？

## 10. 候选方向（全部未实现）

- 可复现每日种子、进阶难度层、战绩/最深层统计。
- 更多随机事件与规则型 Boss、墓园献祭小体系。
- 同种子回放与跨设备排行榜；需要服务端权威和防作弊边界。
- 永久非强度消费（卡背、异画、头像等），需要独立经济评审。
