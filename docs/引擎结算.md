# 引擎结算顺序

> 本文是战斗引擎结算流程的权威描述，改动顺序时必须同步更新。对应实现为 `js/engine.js`，网络快照见 `js/net.js`；函数名是锚点，不写易漂移的行号。玩家向规则见[玩法设计](玩法设计.md)，状态字段见[开发指南](开发指南.md)。

## 一、新对局（`initGame`）

1. 重置 `uid/logLines`，创建 `state`：双方 `newSide()`、`round=0`、`phase='deploy'`、默认无战术、`battleSpeed=1`、`roundSummary=null`、每场遗物计数重置。第四参 `runBattle` 仅在 `startNodeBattle` 调用 `initGame(...,true)` 时为真并写入 `state._runBattle`；普通 `initGame` 默认为 false，不受 `RUN.inBattle` 残留影响。
2. 双方牌组洗牌，各摸初始 5 张。
3. 若 `runRelicActive('arcaneTome','player')` 因 `inRunBattle()` 且已拥有【奥术典籍】而为真：额外摸 2 张，再进入正常轮开始。
4. `startRound()`。
5. 远征节点初始化在 `startNodeBattle` 中覆盖继承生命与 Boss 生命，并同步 `roundSummary.startingHp/endingHp`；这些覆盖不重新洗牌或重复初始摸牌。`inRunBattle()` 统一要求 `state._runBattle && RUN.active && RUN.inBattle`，用于遗物、Boss 与远征结算。

## 二、轮开始（`startRound`）

1. 先幂等调用 `finishRoundSummary()`：正常战斗收尾已完成的摘要不会重复结算；若探针/其他入口直接调用 `startRound`，也能在这里撤除仍激活的战术。随后 `state.round++`，`phase='deploy'`。
2. 双方 `state.tactics` 重置为 `null`，`_tacticsActive=false`，`recalcAuras()`。这里重置的是新一轮选择。
3. 立即调用 `beginRoundSummary()` 创建本轮摘要，记录部署开始的 `startingHp/endingHp`，初始 tactics 为 `null`、`completed=false`；此后部署伤害和死亡也会进入本轮摘要。
4. 记录“第 N 轮·部署阶段”，对每一方依次执行：
   1. **法力**：`maxMana +1`（不超过 `manaCap()`，默认 10）；`mana=max(0,maxMana-burned)`；`burned` 清零。
   2. **行动资格**：场上单位 `canAttack=true`。
   3. **龙女变形**：带 `pendingTransform` 的单位变为绿龙（8/0/16，清空词条与法术），英雄恢复 4 点生命。
   4. **再生**：再生 X 恢复 X 点，不超过上限。
   5. **中毒**：受到毒素层数伤害；不产生反击。
   6. **失明/石化倒计时**：持续轮数 -1，归零时记录解除。
   7. **死亡清理**（`cleanupDead`）：进墓地、亡语、轮次摘要阵亡记录；凤凰之羽可按规则挽救。
   8. **士气环境**：非盖牌墓园单位在场先造成额外 -1；再按参与计算单位的阵营数量结算：一种 +1、两种不变、x≥3 为 `-(x-2)`。墓园/元素和盖牌不参与。
   9. **单位法力**：拥有单位法术的单位 `spellMana +1`，不超过上限。
   10. **骷髅王李奥锐克归来**：带 `_leoricReturn` 的墓地单位回原排；满员失败，返场当轮不再回蓝。
   11. **生还的宝礼**：按本步从墓地召唤次数摸牌。
   12. **摸一张牌**（`drawCard`）：牌库空则疲劳 +1并经 `damageHero` 受到递增伤害；手牌满则烧毁。
5. 若 Boss【万籁俱寂】且游戏未结束：敌方召唤一个骷髅到前排。
6. `checkGameOver()` → `render()`。
7. 双人/联机确定本轮部署方：每轮轮换，`deploySide` 与 `_firstSide` 记录；热座显示交机隐私屏，host 广播等待部署。

## 三、部署阶段

- **出牌**（`playCard`）：检查阶段、部署方、费用、场上上限；单位入场，法术走 `playSpellCard`。普通新牌当轮可行动。
- **收回**（`recallMinion`）：仅本轮从手牌打出且 `recallable` 的单位；有不可逆入场效果、已施放单位法术、召唤物/token 不可收回。退还实际支付法力，手牌满不可收回。
- **姿态**：`toggleDefense/toggleLand/flipUnit` 按权限执行；盖牌默认守备，翻开补结算战吼，盖放法术壳翻开立即结算。
- **布阵**（`moveMinion`）：前/中/后/空中按飞行规则落位，可调整同排顺序。
- **战术**（`setTactic`）：每方可选 `assault/guard/rally/null`，部署期可改；人机/热座/host/guest/观战权限不同，guest 发给 host 校验。
- **速度**（`setBattleSpeed`）：仅接受 1/2/4，表现参数；guest 由 host 接收并广播。

## 四、进攻阶段开始（`startCombat`）

1. `flushPendingClick()`，清除法术选目标/墓地浮层；`state.phase='combat'`，记录阶段日志。
2. AI 模式依次完成：`aiPlayStep` 循环出牌 → `aiCastSpells` → `aiSetDefense`。
3. 若 AI 部署已导致游戏结束，停止，不激活战术或启动新 tick。
4. **激活战术**（`activateTactics`）：
   1. AI 通过 `chooseAITactic` 根据自身和公开场面选择。
   2. `_tacticsActive=true`，再次调用 `beginRoundSummary()`；因为当前轮摘要已存在，此处只把 tactics 更新为双方实际选择，不重建对象、不改 `startingHp`，并保留部署阶段伤害与名单。
   3. 猛攻：在 `recalcAuras` 为己方单位当轮攻击 +1；坚守：在 `effArmor` 为己方单位当轮有效护甲 +1。
   4. 集结：逐单位 `changeMorale(+2)`，把实际获得量写入 `m._tacticRally`；免疫、盖牌、上限和 Boss 锁士气仍生效。
   5. 写战术日志与 `roundSummary.keyResults`。
   6. 若拥有【昂扬战旗】且非心如止水：远征玩家全军 `changeMorale(+1)`，记录实际提升和关键结果。
5. **鼓舞/威吓**：双方分别求和后结算全场士气，盖牌不算。
6. **重置战斗计数**：`counterLeft=max(1,反击X)`，额外行动与影遁标记清零。
7. `render()`，以 `setTimeout(combatTick,battleDelay(650))` 启动表现循环。

## 五、每次行动（`combatTick`）

1. 游戏已结束则只补绘并停止。
2. **选择行动者**（`nextActor`）：在可行动、非守备/盖牌/失明/石化且已觉醒的单位中，取 `speedOf` 最高者；并列随机。速度 = 当前攻击 + 有效护甲 + 当前生命，骑兵 ×2。猛攻/坚守/磐石徽记等派生可改变该值。
3. 没有行动者：`finishRoundSummary()` → `startRound()`。
4. **负士气判定**：失败则 `canAttack=false`，记录无法行动与低落表现；随后按 `battleDelay(650)` 安排下一 tick。
5. **目标选择**（`autoAttack`）：
   - 近战：按地面暴露宽度加权随机；刺客/和平等修正。
   - 远程：无视遮挡，优先飞行；再按有利击杀/交换和低生命目标启发式。
   - 无法选随从且满足守备墙/远程防线/可达性条件时攻击英雄；0 攻或无合法目标则跳过。
6. **攻击与伤害**（`doAttack/attackDamage/dealAttackDamage`）：
   - 对单位：`max(0,当前攻击−max(0,有效护甲−穿透))`，再按远程飞行/破法/背刺等词条修正。
   - 对英雄：经 `damageHero` 造成当前攻击点伤害并计入摘要。
   - 英雄的其他伤害（疲劳、相应法术）也必须经 `damageHero`，避免摘要漏计。
7. **反击**（`executeCounter`）：
   - 普通：受到攻击伤害且存活，有次数、攻 >0、够得到来源时立即反击并耗 1 次；远程/免反击/骑兵等按规则过滤。
   - 守备：近战攻击时无限次同时结算，即使守备方将死也反击；不耗普通次数，但仍受士气/失明/石化/觉醒和远程限制。
   - 反击不再触发反击；荆棘盾牌为远征玩家反击伤害 +2。
8. **士气流转**：正面攻击伤害使来源 +1、受伤者 -1、击杀额外 +1；完全格挡时守方 +1，守备格挡普通攻击时来源额外 -1。
9. **击杀/死亡**：
   - 攻击/反击击杀敌方单位时，【鲜血圣杯】使远征玩家英雄恢复 2（不超过上限）。
   - `cleanupDead` 先处理【凤凰之羽】每场首次挽救（以 1 血留场，不计阵亡），其余单位进墓地、写 `unitsLost`、触发亡语。
10. **正士气额外行动**：行动后按当前士气概率触发，每单位每阶段最多一次；恢复 `canAttack` 并由同一单位立即再次 `autoAttack`，不重排全队顺序。
11. `checkGameOver()`、`render()`；未结束则按当前速度安排下一 tick。表现清理也可使用 `battleDelay`，但不能改变随机调用或规则顺序。

## 六、轮次摘要（`begin/finishRoundSummary`）

每次 `startRound` 在部署开始即创建：

```js
{
  round,
  tactics: {player, enemy},
  heroDamage: {player: 0, enemy: 0},
  unitsLost: {player: [], enemy: []},
  startingHp: {player, enemy},
  endingHp: {player, enemy},
  outcome: 'ongoing',
  completed: false,
  keyResults: [],
}
```

- `beginRoundSummary` 在当前轮已有未完成摘要时只更新 tactics；因此 `startCombat/activateTactics` 会写入双方实际选择，但不重建对象、不改变 `startingHp`，也不清空部署阶段数据。
- `currentRoundSummary` 只接受当前轮且未完成的对象；`recordRoundKey` 保留最新 16 条关键结果。
- 英雄伤害在部署和进攻阶段发生时均累计；阵亡在清理时记录；详细 `logLines` 不被摘要替代。只有轮末或致死才由 `finishRoundSummary` 将 `completed=true`。
- 全部行动完成或游戏结束时 `finishRoundSummary`：
  1. 按 `_tacticRally` 撤回集结实际值并删除临时标记；`_tacticsActive=false`，`recalcAuras()`。
  2. 写 `endingHp` 与 `outcome`（ongoing/player/enemy/draw）。
  3. 标记 `completed=true`，输出双方英雄伤害、双方阵亡数与战术的轮次总结日志。
- 下一次 `startRound` 生成新摘要对象，不累积历史大数组；快照只带当前摘要。这里的完整字段是状态/快照契约，不表示紧凑 UI 全部直接显示：UI 只显示双方英雄伤害、阵亡数和结果，战术由当前徽标确认，名单与关键结果由详细日志确认。

## 七、游戏结束（`checkGameOver`）

1. 任一英雄生命 ≤0 即标记 `gameOver`，先 `finishRoundSummary` 记录 player/enemy/draw。
2. 只有 `inRunBattle()` 为真才分流到 `roguelikeBattleEnd`：双方同死算涉险过关并以 1 血续命；否则按胜败进入奖励或纪念流程。普通 `initGame` 没有 `_runBattle`，即使 RUN.inBattle 残留也继续普通结算。
3. 普通人机：胜 100 / 平 50 / 负 30 金币；热座共享收藏有胜者 100、平局 50。
4. 显示结果和金币，保存经济；不再启动后续战斗 tick。

## 八、联机一致性

- host 执行上述全部流程；guest/观战只应用 `makeSnapshot` 的个性化结果。
- 快照包含 `tactics/tacticsActive/battleSpeed/roundSummary`，`applySnapshot` 对缺失字段给兼容默认值。
- 新动作必须同时有 host 权限校验和客户端拒绝反馈；不能靠 guest 本地跑 `combatTick` 补状态。
- 摘要和关键结果属于公开信息，新增记录不得泄露未揭示盖牌、对手手牌或牌库顺序。
