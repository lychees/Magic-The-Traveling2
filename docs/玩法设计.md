# 玩法设计：构筑、战术与远征

> 本文描述本次现代化版本的实际玩法与调平衡方法。词条全表以游戏内卡牌详情和 `cards.json` 为准；逐函数结算以[引擎结算](引擎结算.md)为准；接口字段以[开发指南](开发指南.md)为准。后续想法统一放入[现代化重构](现代化重构.md#7-候选路线图全部未实现)，不在本文冒充现状。

## 1. 产品愿景

**一句话**：一款中文、零安装的三排自动战斗卡牌游戏——玩家在部署期做少量高价值决定，在战斗期看懂阵型、护甲、反击和士气共同产生的结果。

设计支柱：

1. **少而重要的决定**：每轮围绕费用、站位、姿态与一种战术指令做选择，不要求逐单位点击攻击。
2. **结果可以解释**：每次伤害、反击、士气触发与战术来源都能在卡面、详情、日志或轮次摘要中找到。
3. **构筑有不同解法**：单/双/多阵营有士气取舍，三排与远程/飞行形成空间解法，远征遗物进一步改变资源与交换方式。
4. **即开即玩但可持续深挖**：预设卡组让新玩家立即开局；398 张卡、编辑器、热座/联机和 10 列远征服务长期玩家。

## 2. 目标用户与场景

| 用户 | 首要需求 | 对应设计 |
| --- | --- | --- |
| 首次接触的中文玩家 | 不读长规则也能完成首轮 | 阵营预设、30 秒引导、上下文提示、可折叠完整规则 |
| 喜欢构筑与自动战斗的玩家 | 阵型、词条、战术有组合空间 | 20–60 张构筑、三排遮挡、三种当轮战术、AI 对战 |
| Roguelike 玩家 | 每局成长不同，奖励能改变打法 | 分支路线、生命继承、抓牌/删牌/篝火、8 种遗物 |
| 同机或远程朋友 | 规则一致、私有信息不泄露 | 热座隐私屏；PeerJS 房主权威与个性化快照 |
| 收藏与创作者 | 卡面有仪式感，能快速试验内容 | 三主题、3D 检视/卡包/集卡册、卡牌编辑器 |
| 窄屏与键盘用户 | 核心流程不依赖精确拖拽/悬停 | 响应式、按钮等价操作、可见焦点、减少动态效果 |

桌面是主要战场场景；约 390px 窄屏必须能完成核心流程。触屏不是“缩小桌面”，拖拽不是唯一入口。

## 3. 核心循环

### 3.1 一场对局

`构筑牌组 → 初始 5 张手牌 → 轮开始/资源恢复 → 部署与布阵 → 选择战术 → 自动战斗 → 阅读轮次摘要 → 下一轮 → 结算奖励`

- **部署前**：评估手牌费用、现有场面、英雄生命和对方公开阵型。
- **部署中**：打出单位/法术、切守备、盖放、施放单位法术、调排与左右顺序。
- **开战前**：选择猛攻、坚守、集结，或保持无指令；最后确认。
- **战斗后**：用摘要和详细日志复盘，下一轮修正，而不是只等待随机结果。

### 3.2 构筑与收藏循环

`对局/远征获得金币 → 开卡包或阵营卡盒 → 补充收藏数量 → 调整牌组 → 再对战`

首次运行已经拥有全部 398 种卡各 4 张和 200 金币，因此“开包”主要增加拥有数量和收藏体验，不阻挡基础构筑。金币没有付费购买渠道。

### 3.3 远征循环

`选阵营与 15 张起始牌组 → 选连通节点 → 继承生命战斗/休整 → 抓牌与遗物成长 → 中 Boss → 后续构筑 → 最终 Boss → 通关或纪念卡结算`

单场战斗追求赢；整场远征还要管理生命、牌组厚度、删牌、治疗与遗物协同。

## 4. 30 秒上手

以下使用默认规则，不要求先读词条全表。

| 时间 | 操作 | 界面反馈/判断 |
| --- | --- | --- |
| 0–5 秒 | 保持“人机对战”，在预设区选择一个“阵营 · 标准” | 立即获得 30 张合法牌组；也可选帕斯卡/艾达预设 |
| 5–10 秒 | 点“开始战斗” | 双方各 5 张起手；第 1 轮开始后有 1 点法力并各摸 1 张 |
| 10–17 秒 | 点一张费用够用的单位手牌 | 近战默认前排，远程默认后排，飞行进入空中；也可拖到指定排/位置 |
| 17–22 秒 | 如需保护英雄，点单位上的“→ 守备表示” | 守备不主动攻击，可无限次同时反击；没有合适单位可跳过 |
| 22–26 秒 | 在战术区选“猛攻 / 坚守 / 集结”之一 | 文案显示本轮攻 +1 / 有效护甲 +1 / 士气 +2；可改选，也可不选 |
| 26–30 秒 | 点“开始战斗”，需要时把表现速度调为 2x | 自动结算；随后阅读本轮摘要与下一轮提示 |

首轮只记住四句话：

1. **前排遮挡后排**，远程无视遮挡。
2. **攻击减有效护甲才是伤害**，护甲每次受击都会减伤。
3. **守备用于托住战线**，集结用于争取额外行动或减少低落失败。
4. **战术只管本轮**，下轮要重新决定。

## 5. 对局基础规则

### 5.1 构筑与开局

- 牌组 20–60 张；同名普通卡最多 4 张且不能超过拥有数；带 `legend` 的传说随从限 1 张。
- 初始英雄生命默认 20，可在组牌规则中改为 10/15/20/25/30；法力上限默认 10，可配置为 5/8/10/12/15。
- 双方起手各 5 张，牌库独立洗牌；没有一方固定先攻击的开局优势。
- 每轮开始双方各增加 1 个法力水晶并补满，直到配置上限；随后经过开始结算并各摸 1 张。
- 手牌上限 10，超出的摸牌被烧毁；双方地面/空中等单位合计安全上限为每方 50，用于防止无限增殖卡死。
- 新部署单位当轮即可行动，没有召唤失调；0 攻单位不会主动攻击。

### 5.2 轮结构

1. **轮开始**：轮数 +1，双方战术选择重置为 `null`，进入部署阶段；上一轮派生修正已在战斗收尾时撤除。
2. **双方轮开始结算**：法力、变形、再生、中毒、失明/石化倒计时、死亡清理、阵营士气、单位法术回蓝、复活/摸牌等，详细顺序见[引擎结算](引擎结算.md)。
3. **部署**：玩家执行合法动作并设置战术；热座/联机按 `deploySide` 依次部署，每轮轮换先手方。
4. **战斗开始**：锁定战术，AI 完成部署/施法/姿态和指令选择；随后激活战术、结算鼓舞/威吓、重置反击与额外行动标记。
5. **自动行动**：直到所有可行动单位都行动或跳过；游戏结束则立即进入结算。
6. **轮次收尾**：`finishRoundSummary` 撤除当轮战术派生修正、完成 `roundSummary` 并输出易读摘要；下一次 `startRound` 再清空双方选择。

### 5.3 胜负与疲劳

- 任一英雄生命 ≤0 即检查结束；双方同时死亡为同归于尽。
- 牌库为空仍要摸牌时，疲劳计数 +1并受到等于新计数的伤害：第一次 1、第二次 2，依此类推。
- 普通人机：胜 100 金币 / 平 50 / 负 30。热座共享本机收藏，有胜者结算 100，平局 50；联机结果不改变房主权威规则。
- 远征中双方同死算“涉险过关”，以 1 点生命继续；普通失败进入纪念卡流程。

## 6. 三排、空中与目标选择

### 6.1 阵型和站位

- 地面三排：前排 `row=0`、中排 `row=1`、后排 `row=2`；双方前排相向。
- 空中 `row=3` 是有效飞行单位的特殊区域，不是第四个地面排。
- 点击手牌：近战默认前排，远程默认后排，飞行默认空中。拖拽可指定排及同排插入位置。
- 部署阶段可拖动己方单位跨排或调整同排左右顺序。飞行正面单位可“落地/起飞”；守备时暂时失去有效飞行。
- 本轮刚打出且满足收回条件的单位可单击收回并退还实际法力；战吼等不可逆入场效果、已施放单位法术、token 等不可收回。双击始终优先用于详情，不执行单击收回。

### 6.2 战场宽度

普通地面单位占 1 宽，守备单位占 2 宽；每排各自居中，最宽排决定共同坐标。前排及更靠前的地面排会遮挡正后方重叠区间。

近战只能选暴露宽度 >0 的合法地面/可及目标，并按暴露宽度加权随机：

- 前排 1 张普通卡，后排 2 张普通卡且几何关系各露一半：命中权重为前 `0.5`、后左 `0.25`、后右 `0.25`。
- 前后排各 1 张且完全对齐：后排暴露为 0，前排存活时不能被该近战选中。
- 守备占 2 宽，会改变遮挡面积，也会提高被若干随机效果选中的权重。

有效飞行不计算地面宽度，既不遮挡也不被遮挡。地面近战不能攻击有效飞行；飞行攻击者和远程可以攻击飞行。刺客另有无视遮挡并偏向后排的规则。

### 6.3 远程与英雄直击

- 远程无视地面遮挡，可攻击任意排，优先攻击有效飞行；在满足条件的合法目标中优先有利击杀，否则偏向低生命目标。
- 近战按暴露宽度随机选目标，不由玩家逐次指定。
- 只有对方场空，或对方所有单位都不是该攻击者的合法目标时，才通常可以直击英雄。
- 但只要对方仍有守备单位（含可被揭示的盖牌守备）或有效远程防线，就必须先清除对应防线。完全够不到的单位不形成保护。
- 守备墙、远程防线和遮挡是三件不同的事；详情/预览用于帮助判断，不要把“后排”等同于“永远安全”。

## 7. 伤害、反击与士气

### 7.1 攻击伤害

普通攻击对单位的基础公式：

`伤害 = max(0, 攻击者当前攻击 − max(0, 目标有效护甲 − 护甲穿透X))`

之后按词条顺序应用特定修正：

- 远程攻击有效飞行：上述减甲后的伤害 ×2。
- 破法攻击拥有单位法术的目标、背刺攻击守备目标：对应伤害 ×2。
- 居高临下、死战、反扑等按各自文案追加。
- 对英雄直接造成攻击者当前攻击点伤害，英雄没有护甲。
- 法术伤害不走攻击护甲公式，但会被“法术护盾X”减免；免疫词条优先。

**例 A**：3 攻攻击 1 有效护甲，造成 2 伤害。选择猛攻后本轮攻击变 4，造成 3 伤害。

**例 B**：4 攻攻击 2 有效护甲，造成 2 伤害。目标方选择坚守后有效护甲变 3，只受 1 伤害。

**例 C**：5 远程攻击 1 护甲的有效飞行单位，先减甲得 4，再翻倍为 8。

**例 D**：攻击 ≤有效护甲时伤害为 0，不产生“负伤害治疗”；完全格挡会进入士气流转。

### 7.2 行动顺序

每个可行动单位的速度为：

`(当前攻击 + 有效护甲 + max(0, 当前生命)) ×（骑兵 ? 2 : 1)`

每 tick 从本阶段尚未行动、非守备/盖牌/失明/石化且已觉醒的单位中选速度最高者；并列随机。速度与 UI 的 1x/2x/4x 完全无关。

### 7.3 普通反击

- 每单位每战斗阶段默认 1 次，`反击X` 改为 X 次；战斗开始重置。
- 单位受到攻击伤害（含溅射）且仍存活，若攻 >0、够得到伤害来源且有剩余次数，就立即反击并消耗 1 次。
- 反击不考虑地面宽度遮挡，但仍遵守飞行可达性、失明/石化/觉醒等限制；够不到或 0 攻不消耗次数。
- 远程攻击以及带“不受反击”的攻击不触发普通反击；骑兵高速免反击与拒马按词条处理。
- 反击不继续触发反击。连击第二次也不触发反击。
- 非攻击伤害（例如中毒）不触发普通反击。

### 7.4 守备表示与盖牌

守备表示：

- 不主动攻击；被近战攻击时，即使会被本次攻击击杀，也与攻击同时结算反击，次数不限且不消耗普通反击机会。
- 守备反击仍可能因负士气失败，也不能反击远程；失明、石化、未觉醒会阻止反击。
- 攻击守备单位时，其守备反击无视攻击方普通“免反击”特性。
- 守备占 2 宽，并被部分随机效果以 2 倍权重选取。

翻面表示：

- 从手牌盖放的单位默认守备，不触发战吼；对手只见卡背。普通盖牌不是攻击目标、不主动行动、不反击，但仍可按规则回蓝/获得增益。
- 盖牌守备可被攻击，并在受击前揭示、补结算战吼。
- 部署阶段可主动翻开；已正面的在场单位不能再次盖回。
- 法术也能盖放为法术壳，不是单位、不可被攻击；翻开时立即结算，需要目标的法术随机选择合法目标。

### 7.5 士气

每单位士气范围 **-10～+10**：

- 正士气 `+x`：该单位行动后有 `x×10%` 概率立即额外行动一次；每单位每战斗阶段最多触发一次。
- 负士气 `-x`：轮到行动时有 `x×10%` 概率无法行动；普通/守备反击也有相同概率失败。
- 额外行动是同一单位立即连续行动，不重新进行全体速度排序。

常规流转：

| 事件 | 士气变化 |
| --- | --- |
| 对单位或英雄造成正面攻击伤害 | 伤害来源 +1 |
| 击杀单位 | 伤害来源额外 +1 |
| 受到攻击伤害 | 受伤者 -1 |
| 攻击被有效护甲完全抵挡 | 防守方 +1 |
| 守备单位完全格挡普通攻击 | 防守方 +1，伤害来源再 -1 |
| 轮开始，参与计算的单位属于同一阵营 | 全体参与计算单位 +1 |
| 两种阵营 | 不变 |
| x≥3 种阵营 | 全体参与计算单位 `-(x-2)` |
| 场上存在非盖牌墓园单位 | 参与士气计算的单位额外 -1 |

墓园与元素单位不受士气影响，也不参与阵营数量计算；盖牌不参与增减或阵营计算。Boss“心如止水”会把士气锁定为 0，因此集结及常规士气流转不能突破该规则。

**集结示例**：某单位从 -1 变为 +1，原本 10% 无法行动/反击失败的风险被移除，行动后还获得 10% 额外行动机会；这不是“必定多动”。

## 8. 每轮战术指令

### 8.1 选择与持续

| ID | 中文 | 当轮效果 | 典型用途 |
| --- | --- | --- | --- |
| `assault` | 猛攻 | 己方单位攻击 +1 | 抢血、提高击杀线、增强攻击与反击 |
| `guard` | 坚守 | 己方单位有效护甲 +1 | 降低每次攻击伤害、保护关键后排/城墙 |
| `rally` | 集结 | 己方单位士气 +2，按实际可获得量记录 | 挽救负士气、提高额外行动概率 |
| `null` | 不选择 | 无战术修正 | 无合适收益或保持默认 |

- 每方每轮最多一个当前值；部署阶段可改选，`setTactic(side, key)` 的合法 key 只有以上三项或 `null`。
- 默认 `state.tactics = {player:null, enemy:null}`。人机玩家只能改己方；热座只能改当前部署方；联机由房主校验，观战者只读。
- 战术在 `startCombat` 中锁定并激活：AI 已完成部署、施法和守备选择，战术激活先于鼓舞/威吓及首个行动者。
- 猛攻和坚守作为当轮派生修正参与攻击/有效护甲计算，不改 `baseAtk`、卡牌 JSON 或永久增益。集结逐单位记录实际增加量，避免超过上限或免疫单位在阶段末被错误扣减。
- 战斗收尾 `finishRoundSummary` 撤除派生修正并完成摘要；下一轮 `startRound` 会幂等再次调用该收尾（不重复结算），再把双方选择重置为 `null`。召唤物/增益等永久效果不因清战术被误删。
- 速度控件与战术独立：速度不能加强、延长或重复触发战术。

### 8.2 精确时序示例

**人机第 N 轮**：

1. 上轮派生修正在上轮战斗收尾时已撤除，本轮选择已重置；本轮阵营士气等开始效果完成。
2. 玩家打出单位、调整姿态，选择 `assault`；此时仍处于部署阶段，可改为 `guard`。
3. 玩家点开始战斗，部署入口关闭。
4. AI 用自己的公开信息完成出牌、单位法术、守备和战术选择。
5. 双方战术各激活一次并写日志；再结算鼓舞/威吓，重置反击/额外行动。
6. 首个单位行动。猛攻已参与速度公式中的“当前攻击”，坚守已参与速度公式中的“有效护甲”。
7. 所有行动结束后撤除第 N 轮派生修正并完成摘要；第 N+1 轮开始重置双方选择。

**热座/联机**：双方各自部署时设置自己的战术；双方部署都完成后才进入同一战斗阶段。后部署方不会获得修改对方战术的权限。

### 8.3 决策示例

| 公开局势 | 建议 | 原因与风险 |
| --- | --- | --- |
| 对方英雄 3 血，己方有 2 攻可直击单位 | 猛攻 | 攻击变 3，达到斩杀线；先确认守备/远程防线确实已清空 |
| 己方关键 5 血后排会被 3 攻单位攻击 | 坚守 | 有效护甲 +1可让每次攻击少 1 伤害；若对方有护甲穿透或法术，收益会变化 |
| 两个核心单位分别为 -2、0 士气 | 集结 | 分别变为 0、+2，一个消除失败风险，另一个获得 20% 额外行动机会 |
| 全队墓园/元素，或 Boss 心如止水 | 通常不选集结 | 士气免疫/锁 0 时没有收益，应比较猛攻和坚守 |
| 对方大量低攻单位、己方高攻反击墙 | 猛攻或坚守 | 猛攻提高反击击杀线；坚守提高每次交换耐受，需按实际攻防计算 |

## 9. 战斗速度与轮次摘要

### 9.1 表现速度

- `setBattleSpeed(n)` 只接受数字 `1 / 2 / 4`，默认 1；控件显示 `1x / 2x / 4x`。
- 1x 的 `combatTick` 间隔为 650ms，2x 约 325ms，4x 约 162.5ms。
- 倍率只缩放表现等待，不改变 `Math.random` 的调用顺序/次数、行动者、目标、伤害、摸牌或奖励。CSS 动画、3D 检视和音频有自己的表现时长，不作为规则计时器。

### 9.2 每轮摘要

`state.roundSummary` 以 `round` 标识所属轮，核心内容包括：

- `tactics`：双方本轮实际战术；未选为 `null`。
- `startingHp / endingHp`：双方战斗激活与收尾时的英雄生命；`heroDamage` 按 side 记录摘要创建后的本战斗阶段英雄伤害。
- `unitsLost`：双方本轮阵亡单位的 `{uid,name}` 列表。
- `outcome`：`ongoing / player / enemy / draw`；`completed` 标记是否已收尾。
- `keyResults`：关键结果说明，例如战术触发、额外行动、Boss/遗物关键节点，最多保留最新 16 条。

摘要是战斗事件的易读视图，不替代 `logLines` 的逐项伤害与词条日志，也不应通过解析中文日志反向生成。下一次战斗激活时创建新对象，不把全部历史摘要塞入存档或网络快照。

## 10. AI 设计

### 10.1 信息边界

AI 可以使用自己的手牌、法力、墓地以及双方公开的英雄/战场状态；不得读取玩家手牌内容或牌库顺序，不得直接修改玩家资源/随机结果。联机时 AI 不替代真人，房主只执行合法动作。

### 10.2 部署与法术

- 可负担卡牌按战斗力评分降序、费用降序处理；单位按远程/飞行/生命/低费炮灰等启发式落排。
- AoE 通常至少有 2 个有效目标才使用；单体伤害/减益优先高攻目标，增益偏向高攻或高价值友方。
- 治疗考虑英雄或单位生命缺口；过牌考虑手牌上限；禁断之炎等自伤牌有生命与场面门控。
- 单位法术消耗自身法力并受共同合法性检查，不免费施放。

### 10.3 姿态与战术

- 低攻高血单位倾向守备；英雄半血以下或场面落后时，大身板单位更倾向筑墙；高攻且非危局倾向攻击表示。
- `chooseAITactic` 只使用 AI 自己的正面非壳单位、这些单位的公开姿态/士气，以及对方正面非壳单位；没有己方有效单位时返回 `null`。
- 进攻方估值考虑可行动攻击者数量 `A`、其攻击总和 `P`：`assault = 2 + 1.2A + 0.15P`；若对方场空且当前攻击总和加猛攻足以斩杀，再加 7；没有攻击者时为 -2。
- 防守估值考虑对方公开攻击表示单位的攻击总和 `I`：`guard = 1.5 + 0.18I + 半血以下4 + 对方单位多2 + 己方守备数`。
- 士气估值考虑可受士气影响单位数 `M`、其中负士气数 `N`：`rally = 1 + 1.1M + 2.5N`；没有可受影响单位或 Boss 心如止水时为负无穷。
- 三项取最高分；同分按随轮数和己方单位数轮换的固定顺序处理，不为战术额外消耗随机数。该启发式不固定随机，也不永远选同一项。
- AI 的目标是可解释的启发式，而不是伪装成“学习型 AI”。当前没有三档难度、神经网络或云端模型。

### 10.4 自动攻击是双方共用规则

双方自动行动都调用同一套目标与伤害逻辑。AI 的“智能”主要发生在部署、法术、姿态与战术，而不是在战斗中获得额外攻击特权。

## 12. Roguelike 远征与遗物

### 12.1 地图与继承

- 选 13 阵营之一，从对应阵营预设中取费用最低的 15 张作为起始牌组。
- 10 列预生成分支地图，第 1 列为起点，第 6 列中 Boss，第 10 列最终 Boss；其他列有 2–3 个节点。
- 节点类型：战斗、精英、篝火、商店、事件、中 Boss、最终 Boss。只能选择与上一节点实际连通的节点。

- 中 Boss 随机“万籁俱寂”（敌方每轮开始召唤骷髅）或“心如止水”（士气锁 0）；最终 Boss“巨龙威压”（敌方单位攻击 +1）。

### 12.3 协同与反制示例

- **战鼓 + 荆棘盾牌**：主动攻击和反击都受益，但遇到远程防线时仍需布阵与解场。
- **磐石徽记 + 坚守**：同一轮进一步提高每次攻击的减伤；护甲穿透、法术和完全格挡后的士气仍按原规则处理。
- **猎手长弓 + 猛攻**：远程核心本轮攻击总共 +3；对有效飞行先减甲再翻倍，爆发高但依赖保住远程防线。
- **昂扬战旗 + 集结**：按各自触发点叠加，士气仍封顶 +10；心如止水会抵消其士气价值。
- **奥术典籍 + 鲜血圣杯**：更多开局选择帮助建立击杀链，击杀回血支持后续节点，但不提供无限抽牌循环。

## 13. 平衡原则与成功指标

### 13.1 调平衡的顺序

1. **先修可读性与错误结算**，再调数值。玩家误解规则时，胜率不能证明设计好坏。
2. **同种子/同随机序列对照**，一次只改一个变量；速度档不得进入平衡变量。
3. **区分人机仿真与真人 meta**。AI 不会用某机制不等于该机制弱，AI 滥用也不等于真人无法反制。
4. **按费用和轮次看影响力**。高费卡要在登场当轮改变局面，低费卡不能同时占据节奏、站场和资源的全部优势。
5. **所有循环有明确上限**：每轮、每阶段、每单位、每场至少一种计数器；检查分裂、复活、摸牌、回血和召唤组合。
6. **战术有场景而非绝对等级**。若某指令跨阵营/轮次长期占绝对多数，先分析使用场景和 AI 估值，再动 ±1 数值。
7. **遗物改变打法，不做无条件乘区叠加**。新增遗物必须列出至少一个协同、一个无效/受限场景和一个循环风险。

### 13.2 每次数值评审必须记录

- 版本/commit、卡池数量、牌组生成方式、AI 版本、是否启用战术与遗物。
- 随机种子或可复现方法、局数、双方方向、平局的计分方式。
- 胜率、平均/中位轮数、费用段出牌率、指令选取率、关键词条触发率。
- 至少一个异常长尾对局和一个典型对局，避免只看均值。

可复用基线命令：`node tools/simulate.js 20`；该脚本仿真默认阵营卡组，不等于真人平衡结论。新增战术/遗物后应先让仿真驱动与实际版本一致，再比较数据。

### 13.3 可量化成功指标

本版本未添加遥测，下列是验收目标和采集方案，不是既有实测结果。

| 指标 | 计算方式 | 首轮目标 | 最低样本/方法 |
| --- | --- | --- | --- |
| 30 秒开局率 | 30 秒内进入首场战斗的新手 ÷ 总新手 | ≥80% | 5 名以上首次玩家，允许使用预设和引导 |
| 首轮核心完成率 | 首轮内完成出牌、姿态/布阵、选指令、开战者 ÷ 总新手 | ≥80% | 观察任务，不由测试者代点 |
| 摘要理解率 | 正确回答英雄伤害、阵亡、战术三题的人数 ÷ 总测试者 | ≥80% | 首轮后立即提问 |
| 指令选取分布 | 某指令选择次数 ÷ 有指令选择总次数 | 单项原则上 ≤70%；超出须给环境解释 | ≥100 局仿真 + ≥10 局人工 |
| 战术留存/使用率 | 至少主动选择一次战术的对局 ÷ 总对局 | ≥80% 人机测试局 | 本地动作记录，不采集个人数据 |
| 遗物有效率 | 通过定向引擎断言的遗物数 ÷ 遗物总数 | 8/8 | 每个效果至少一个正例和一个边界例 |
| 远征路线差异 | 同阵营不同遗物组合在选取战术、生命消耗或构筑上的可解释差异 | 至少 3 类可复现路线 | 定向场景 + ≥20 次奖励流程 |
| 窄屏任务完成率 | 390px 下无协助完成核心任务数 ÷ 任务总数 | 100% | 构筑到开战、切守备、选战术、调速、读摘要 |
| 控制台稳定性 | 核心流程新增未处理异常数 | 0 | 三主题各一轮，另测联机快照与旧档恢复 |
| 长局性能 | 连续 10 轮以上是否出现持续卡顿/失控定时器 | 无阻断；4x 不积压 | Performance/Memory 记录实际设备与场景 |

### 13.4 平衡调整判定示例

- **猛攻选取率 >70%且胜率显著偏高**：先分解是否集中在斩杀轮或少数阵营，再考虑降低 AI 选取倾向、加强其他指令的场景价值，最后才改攻 +1。
- **坚守导致平均轮数长尾增加**：检查完全格挡与守备无限反击，而不是直接降低所有护甲；记录轮数 P50/P90 和疲劳率。
- **集结选取低**：区分玩家不理解概率、墓园/元素环境过多、额外行动收益不足三种原因；先改善反馈，再决定是否调整 +2。
- **某遗物必选**：比较“拿到/未拿到”在同节点、同牌组下的胜率与生命差，并检查三选一候选分布，不能只看通关玩家都带它。
