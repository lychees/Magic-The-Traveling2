# 使魔卡牌对战（Magic The Traveling）

H3 题材的中文三排卡牌对战游戏：组牌、布阵、选择每轮战术，然后观看自动战斗并用轮次摘要复盘。零构建纯静态，主游戏打开 `index.html` 即玩。

在线地址：<https://lychees.github.io/Magic-The-Traveling2/>

## 本次现代化版本

- **现代三栏构筑**：对局设置/预设、可搜索筛选排序的卡库、牌组与完成度/法力曲线分区。
- **每轮战术**：猛攻 `assault`（攻 +1）、坚守 `guard`（有效护甲 +1）、集结 `rally`（士气 +2），只持续当轮，开战前可改选。
- **可读战斗**：1x/2x/4x 表现速度、每轮摘要、详细日志、单位状态与卡牌详情。
- **三主题**：深色烫金 `default`、皮革拟物 `skeuo`、像素 RPG `pixel`；同一套功能与规则。
- **更易上手**：首轮组牌/战斗引导、键盘操作、可见焦点、减少动态效果支持、桌面与约 390px 窄屏布局。
- **远征成长**：10 列分支地图，8 种真实生效的遗物，精英/Boss 后独立三选一，存档可恢复。

既有能力保留：13 阵营、398 张卡（336 单位 + 62 法术）、人机/同机热座/PeerJS 联机与观战、预设/随机牌组、收藏与卡包、3D 集卡册、卡牌编辑器、3D 全息检视和程序合成音效。

## 30 秒开始

1. 保持“人机对战”，在预设区选择一个“阵营 · 标准”，立即得到 30 张合法牌组。
2. 点“开始战斗”。双方起手 5 张，第 1 轮有 1 点法力并各摸 1 张。
3. 点击一张费用够用的单位：近战默认前排，远程默认后排，飞行进入空中；也可拖到指定排/位置。
4. 需要防守时，点单位上的“→ 守备表示”。
5. 选择一种本轮战术，或不选；需要时把战斗速度调为 2x。
6. 点“开始战斗”，随后用紧凑摘要查看双方英雄伤害、阵亡数和结果；在当前战术徽标与详细日志中确认战术，在详细日志中确认具体名单及关键结果。

首次运行已有全部 398 种卡各 4 张和 200 金币，不需要先抽卡才能组牌。

## 对局规则速查

### 构筑与轮次

- 牌组 20–60 张；同名卡最多 4 张且不超过拥有数，传说随从限 1 张；手牌上限 10。
- 默认英雄 20 生命，法力上限 10；每轮双方水晶 +1并回满、各摸 1 张。组牌规则区可调整生命、法力上限、盖牌与守备开关。
- 每轮分**部署阶段**与**进攻阶段**。部署时出牌、施法、布阵、切姿态、选战术；进攻时双方单位自动行动。
- 行动速度 = 当前攻击 + 有效护甲 + 当前生命，骑兵 ×2；高者先动，并列随机。这里的速度与 1x/2x/4x 表现速度无关。
- 新单位当轮可行动。击倒对方英雄获胜；牌库抽空后的摸牌造成递增疲劳伤害。

### 三排与伤害

- 地面为前/中/后三排；有效飞行位于空中，不占地面宽度。
- 普通单位占 1 宽，守备占 2 宽。前排遮挡正后方，近战按暴露宽度加权随机选目标；远程无视遮挡并优先攻击飞行。
- 攻击伤害 = `max(0, 当前攻击 − 扣除穿透后的有效护甲)`；远程攻击有效飞行时，先减甲再 ×2。
- 法术伤害不走攻击护甲，但受法术护盾/免疫影响。
- 守备/远程防线及目标可达性共同决定能否直击英雄，不是“场上有任意单位就永远打不到英雄”。

### 反击与守备

- 普通单位每战斗阶段默认 1 次反击，`反击X` 为 X 次；受到攻击伤害且存活、攻 >0、够得到来源时触发。
- 远程攻击不触发普通反击；反击不继续触发反击。
- 守备单位不主动攻击，被近战攻击时无限次同时反击，即使被击倒也完成该次反击；仍受士气、失明、石化、觉醒和远程限制。
- 盖放单位默认守备且不先触发战吼；盖牌守备可被攻击并在受击前揭示。法术也可盖放，翻开时结算。

### 士气

- 每单位士气 -10～+10。
- 正士气每点提供 10% 概率在行动后立即额外行动一次，每单位每战斗阶段最多一次。
- 负士气每点对应 10% 无法行动及反击失败概率。
- 造成攻击伤害 +1、击杀额外 +1、受攻击伤害 -1；完全格挡会改变双方士气。
- 轮开始：单一阵营 +1，两阵营不变，x≥3 阵营为 `-(x-2)`。墓园/元素与盖牌不参与；非盖牌墓园单位另有全场士气压制。
- 心如止水 Boss 会锁定士气为 0，集结也不能突破。

完整公式与示例见[玩法设计](docs/玩法设计.md)，逐函数顺序见[引擎结算](docs/引擎结算.md)。

## 每轮战术与战斗速度

| 战术 | 当轮效果 | 适合场景 |
| --- | --- | --- |
| 猛攻 | 己方单位攻击 +1 | 抢血、提高击杀与反击能力 |
| 坚守 | 己方单位有效护甲 +1 | 降低每次攻击伤害、守住关键单位 |
| 集结 | 己方单位士气 +2 | 挽救负士气、争取额外行动；受上下限/免疫/Boss 限制 |

- 每方每轮最多一种，默认无指令；部署阶段可改选或取消。
- 战术在进攻阶段开始激活，战斗收尾撤除，下一轮重新选择；不修改卡牌基础值。
- AI 根据自身与公开场面选择，不读取玩家私有手牌。
- 热座和联机双方只能改自己的指令，观战者只读。

`1x / 2x / 4x` 只缩短表现等待，不改变行动顺序、随机序列、伤害、奖励或胜负。每轮紧凑摘要只显示双方英雄伤害、阵亡数和结果；当轮战术由当前战术徽标确认，具体阵亡名单、战术触发和其他关键结果由详细日志确认。`state.roundSummary` 保存的结构化字段不等于全部在 UI 直接可见。

## 操作

- **单击卡库卡牌**：加一张；**单击牌组条目**：移除一张。
- **单击手牌**：打出；需要目标的法术会进入选目标模式，点空白或再次点击可取消。
- **拖拽手牌/单位**：指定排和顺序；点击出牌与守备按钮是无拖拽替代路径。
- **双击卡牌**或聚焦后 **Shift+Enter**：查看详情/3D 检视，不执行待定的单击动作。
- **Enter / Space**：激活聚焦按钮或卡牌默认动作；**Tab / Shift+Tab**：移动焦点；**Esc**：关闭允许取消的浮层。
- **长按战场单位**：打开进攻/受击战术预览。
- **单击牌库/墓地**：查看列表；牌库不暴露抽牌顺序。
- **顶栏“画风”**：切换三主题；音效按钮切换静音。

## 游戏模式

### 同机双人与联机

- 热座：玩家 1 组牌 → 交机 → 玩家 2 组牌；每轮依次部署，隐私屏隐藏手牌，每轮轮换部署先手。
- 联机：PeerJS 房间码，可设轻量密码并支持观战。房主浏览器权威执行规则并广播个性化快照；对手和观战者看不到不应公开的手牌/盖牌。
- 房间密码不是账号认证或防作弊；公共 P2P 不保证可达，当前不支持断线重连。

### Roguelike 闯关

选择阵营与 15 张起始牌组，沿 10 列实际连线选路。生命 25 点跨节点继承；节点包括战斗、精英、篝火、商店、事件、中 Boss 与最终 Boss。

- 普通/精英/中 Boss 胜利基础金币：30 / 60 / 120；最终 Boss 300，并有随机 7 费以上本阵营卡入库。
- 篝火：恢复 8 生命，或选牌承担 70% +1攻/+2血、30% 销毁。
- 商店：删牌 50、随机本阵营卡 100、恢复 6 生命 40，使用永久金币。
- 中 Boss：万籁俱寂或心如止水；最终 Boss：巨龙威压。失败生成纪念卡，进度自动保存。

本次 8 种遗物：**战鼓、磐石徽记、猎手长弓、荆棘盾牌、昂扬战旗、鲜血圣杯、奥术典籍、凤凰之羽**。它们只作用于远征玩家侧；精英/Boss 后从未拥有遗物中三选一。完整精确效果见[玩法设计 · 遗物](docs/玩法设计.md#122-本次-8-种遗物)。

### 收藏、卡包与 3D

- 普通对局金币：胜 100 / 平 50 / 负 30。
- 扩充卡包 100（全卡池 5 张）、阵营卡包 150（指定阵营 5 张）、阵营卡盒 600（同阵营 5 包）。
- 3D 集卡册每集齐一个阵营可领取一次随机传说卡；纪念卡进入纪念堂。
- `index.html#holo` 或 `card-viewer.html` 进入 3D 检视：拖拽旋转、覆膜工艺、开包/卡盒、导出 PNG。
- 收藏、金币、主题、引导和远征存于本机 localStorage；清站点数据会丢失，没有云同步。

## 本地运行与验证

无需安装或构建。主游戏可直接打开 `index.html`；完整 3D importmap 需要 HTTP：

```bash
python3 -m http.server 8474 --bind 127.0.0.1
# http://127.0.0.1:8474/
```

改卡只编辑 `cards.json`，然后同步，不要手改 `index.html#cards-json`：

```bash
node tools/sync-cards.js
# 仅在明确要按统一公式重算全部评分时：
node tools/sync-cards.js --recompute

# 语法与仿真命令
for f in js/*.js tools/*.js; do node --check "$f" || exit 1; done
node tools/simulate.js 20
```

完整测试矩阵、内联脚本检查、浏览器验证和 GitHub Pages 发布/回滚步骤见[开发指南](docs/开发指南.md)。文档中的验收目标是检查项，不代表本仓库自动宣称所有测试已执行。
